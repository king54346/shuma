# 數碼精靈 Go 服务端复刻计划

目标是让本地 APK 通过原有协议完成登录、选服、进主城、新手引导和普通关卡，再按实际使用路径补齐其他玩法。以雷电模拟器的实际请求、Lua 客户端的字段读取和可重放的报文作为验收依据。

## 现有模块

| Go 包 | 职责 |
| --- | --- |
| `internal/config` | 监听端口、客户端版本、区服配置 |
| `internal/httpservice` | 版本、公告、区服、上报和敏感词 HTTP 服务 |
| `internal/protocol` | WANetTask 帧、CRC、AES、LZ4 和 MessagePack |
| `internal/tcpserver` | TCP 连接、帧收发、请求分发和连接回收 |
| `internal/login` | 登录检查、区服确认、进服和登录结束 |
| `internal/game` | 本地角色、登录快照、新手奖励、卡牌、阵容和普通关卡 |

`main.go` 负责组装监听器和各服务。当前版本使用单个内存角色，重启进程会重新初始化。默认 TCP 回包兼容现有客户端，未实现路由会写入服务端日志。

## 实施顺序

1. **建立联调基线，已完成。** 使用雷电模拟器的 ADB reverse，把登录和游戏 TCP 流经本机转发分别保存上下行字节。用 `adb logcat` 对照客户端的路由、`synID` 和 Lua 栈。通过 IDA MCP 分析 `libcocos2dlua.so` 的资源加载，解出 APK 中用于核对模型、奖励和字段类型的 Lua 配置。
2. **修复登录后的主城和首个奖励，已完成。** `/game/login` 初始化钓鱼和随机塔模型，验证 `select_scene`、`is_auto`、`point_award` 的报错消失。为 `guideCsvID=103` 同步卡牌、角色列表和进度，实际显示皮卡丘。重复请求重放奖励和当前同步信息，同一角色只发放一次。另接入配置里的 164、342、500，待模拟器触发后验收。
3. **补齐首章战斗闭环。** 当前已观察到模拟器完成 1-1 胜利结算。继续抓取失败和领取星级奖励请求。根据客户端提交的 `battleID`、`gateID`、`result`、`star` 处理战斗实例，补齐体力、经验、重复结算和星级解锁。验收时分别打一场胜利和失败，重放结算并检查进度及奖励只更新一次。
4. **保存角色与会话。** 按账号和区服隔离角色，持久化背包、引导、领取记录、阵容和关卡进度。将状态变更与奖励记录放入同一个事务，并测试服务重启后重登和重复领奖。根据客户端的握手和空闲连接日志补齐进服凭据、会话密钥切换与心跳。
5. **逐项扩展已触发的玩法。** 按模拟器实际流程补完新手选择与芯片奖励、主城事件、卡牌养成、任务、背包和商店。在新增路由时记录请求、`view`、`model`、`sync` 及错误码，逐个替换占位响应。SDK 初始化和 APK 音效资源报错单独核对。

## 本轮抓包对照

| 路由 | 修复前 | 修复后 |
| --- | --- | --- |
| `/game/login` | 两个模型缺失，主城触发四次初始化警告 | 客户端进入主城，三个字段的警告未再出现 |
| `/game/role/guide/newbie/award` | 请求包含 `guideCsvID=103`，回包只有 `ret=true` | 回复包含 `view.carddbIDs` 和模型增量，客户端打开精灵奖励界面 |
| `/game/lottery/card/draw` | 卡牌 `nvalue` 为空，抽卡详情出现 `anchorPoint` Lua 错误 | 以本地值 12 初始化六项资质，原始请求重放通过，模拟器打开精灵详情后继续到布阵引导 |

协议回归使用现有真实登录帧。新手奖励测试覆盖发卡、重试和同进程重新登录的状态。

音效报错已抽查到打包差异。同一个报错 MP3 在原包里是 ZIP Stored，在本地 APK 里是 Deflate。客户端用 Android 的 `AssetManager.openFd` 打开该资源，后续可在客户端重新打包时修复。
